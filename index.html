Panduan Operasi Framework

Dari nol sampai submit report. Ikuti bagian demi bagian secara urut. Yang perlu kamu ketik di Terminal ditandai gelap; yang perlu kamu kirim ke Claude ditandai hijau. Jangan lompati bagian mana pun pada run pertamamu.

1

Pahami dulu: ini sebenarnya apa

"Framework" di sini bukan satu aplikasi. Ini tiga lapis yang bekerja sama di dalam Claude Code (asisten AI yang jalan di Terminal):

LapisIsinya apaTugasnya
Skillfolder security-audit berisi metodologimemberi tahu AI apa yang dicek & caranya
Agentsesi Claude Code yang kamu jalankanyang mengeksekusi pengujian
Harnessskrip validate-findings.cjs + schemamengecek temuan itu benar, bukan tebakan

Kamu berperan sebagai orkestrator: kamu yang menyuruh tiap lapis bekerja pada waktunya, lewat perintah dan prompt di panduan ini.

2

Yang perlu disiapkan sekali saja

Cek dulu semua ini ada di komputermu. Buka Terminal, ketik tiap perintah, pastikan keluar versinya (bukan error "command not found"):

Ketik di Terminal
node -v      # harus muncul versi, dibutuhkan validate-findings.cjs
claude       # memastikan Claude Code terpasang
ls ~/.claude/skills/security-audit/SKILL.md   # skill sudah terpasang?
  • Node.js terpasang (node -v keluar versi)
  • Claude Code bisa dijalankan
  • Skill security-audit ada di ~/.claude/skills/
  • Kamu terdaftar resmi di sebuah program bug bounty

Kalau salah satu gagal: balik ke langkah setup skill yang sudah kita kerjakan, atau pasang Node.js lebih dulu. Jangan lanjut sebelum empat kotak di atas tercentang.

3

Buat folder kerja untuk target

Tiap target/engagement punya satu folder sendiri. Di dalamnya kita simpan aturan main dan hasilnya.

Ketik di Terminal
mkdir -p ~/hunting/target-pertama/recon
cd ~/hunting/target-pertama
touch engagement-rules.md

Sekarang buka engagement-rules.md dengan editor apa pun dan isi. File inilah pagar pengaman yang dibaca AI sebelum menyentuh apa pun.

4

Isi aturan main — WAJIB sebelum apa pun

Minimal isi hal-hal ini. Ganti semua tanda <...> dengan punyamu:

Isi ke engagement-rules.md
## Program
Nama      : <mis. Acme di HackerOne>
Link scope: <link halaman scope resmi>
Tgl cek   : <hari ini, scope sering berubah>

## In-scope (HANYA ini yang boleh disentuh)
- api.target.example
- *.target.example

## Out-of-scope (jangan disentuh)
- <subdomain pihak ketiga, staging internal, dll>

## Akun uji (JANGAN kredensial asli)
- Attacker: <email+attacker> / <password>
- Victim  : <email+victim>   / <password>

## Batas
- Maks 2 request/detik
- Stop: 3 temuan terkonfirmasi ATAU 60 menit
- Dilarang: uji endpoint hapus/transfer di produksi

Pintu merah. Kalau ragu sebuah aset in-scope atau tidak, anggap OUT dan jangan sentuh. Scope salah di sini berarti kamu menguji di luar izin, dan itu tanggung jawabmu penuh.

5

Jalankan Claude Code

Dari dalam folder target tadi, nyalakan Claude Code:

Ketik di Terminal
cd ~/hunting/target-pertama
claude

Setelah masuk, pastikan skill-nya kebaca. Ketik:

Kirim ke Claude
/skills

Pastikan security-audit muncul di daftar. Kalau tidak muncul, keluar (Ctrl+C), perbaiki posisi skill, lalu ulangi.

6

Fase Recon — memetakan, belum menguji

Copy prompt ini ke Claude. AI akan membaca aturan main dan memetakan permukaan serang tanpa mengirim serangan apa pun.

Kirim ke Claude
Baca engagement-rules.md dulu. Pakai skill security-audit.
Jalankan fase RECONNAISSANCE untuk satu target in-scope.
Petakan endpoint dan klasifikasikan jadi sinyal. JANGAN kirim
payload apa pun. Simpan hasil ke recon/surface.json.

Tanda benar: AI membuka file RECONNAISSANCE.md milik skill, dan di akhir ada file recon/surface.json. Buka file itu, pastikan semua isinya in-scope.

7

Fase Hunting — satu kelas vuln dulu

Jangan uji semua sekaligus. Untuk run pertama, pilih IDOR (paling mudah dibuktikan). Copy prompt ini:

Kirim ke Claude
Jalankan fase HUNTING dari recon/surface.json.
Fokus HANYA ke IDOR/Broken Access Control.
Pakai 2 akun uji di engagement-rules, maksimal 2 request/detik.
Kumpulkan kandidat beserta bukti mentah (request + response).
JANGAN simpulkan sebagai temuan dulu, itu tugas fase berikutnya.

Awasi di sini. Kalau AI mulai menyebut aset yang tidak ada di surface.json, hentikan dan ingatkan soal scope. Itu feedback untuk memperketat aturan mainmu.

8

Fase Validasi — gerbang anti-slop

Ini bagian terpenting, yang membedakan temuan asli dari sampah. Jalankan skrip pengecek bawaan skill:

Kirim ke Claude
Validasi semua kandidat pakai validate-findings.cjs terhadap
report-schema.json. Buang yang tidak punya bukti (no_proof).
Tunjukkan rekap: candidates N -> confirmed X, rejected Y,
beserta alasan tiap penolakan.

Tanda benar: skrip benar-benar dieksekusi, dan jumlah confirmed lebih kecil dari candidates. Kalau semua kandidat jadi "confirmed", gerbangnya tidak bekerja, periksa ulang.

9

Fase Report — tolak dirimu dulu, baru tulis

Sebelum menulis laporan, suruh AI menjadi pihak program yang mencari celah untuk menolak temuanmu. Baru setelah lolos, tulis laporannya.

Kirim ke Claude — langkah A
Sekarang jadi triager program. Cari semua alasan untuk MENOLAK
tiap temuan confirmed: scope, duplikat, bukti kurang, dampak
dibesar-besarkan. Tunjukkan yang lolos dan yang gugur.
Kirim ke Claude — langkah B
Tulis report untuk temuan yang lolos, sesuai report-schema.
Satu paragraf per section, sertakan request mentah dan langkah
reproduksi. Jangan pakai em-dash. Jangan translate istilah teknis.

Periksa sendiri hasilnya, lalu submit lewat platform bug bounty-mu. AI tidak submit untukmu, kamu yang pegang kendali akhir.

10

Kalau tersendat — perbaikan cepat

GejalaSebab & solusi
Skill tidak muncul di /skillsPosisi SKILL.md salah atau folder dobel. Cek: find ~/.claude/skills/security-audit -iname SKILL.md
Muncul tapi tidak pernah kepakaiSebut eksplisit di prompt: "pakai skill security-audit".
validate-findings.cjs errorNode.js belum ada. Cek node -v, pasang kalau kosong.
AI menyentuh aset out-of-scopeHentikan segera. Pertajam daftar in/out-scope di engagement-rules.
Semua kandidat jadi "confirmed"Gerbang tidak jalan. Minta validasi ulang pakai skrip + schema secara eksplisit.

Pengingat etik. Seluruh panduan ini hanya untuk target dengan izin tertulis: program bug bounty resmi atau pentest berkontrak. Menguji sistem tanpa izin adalah ilegal. Aturan scope bukan formalitas, dan kamu bertanggung jawab penuh atas setiap tindakan yang dijalankan AI atas perintahmu.
